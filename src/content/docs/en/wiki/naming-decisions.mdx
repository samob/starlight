## Naming principle — harness-agnostic by default

Name a thing by what it **is**, not by the harness that happens to be the
current default:

- **Neutral concept** (any harness has one — a session id, an event type,
  autospawn, "the agent") → a **neutral name**. The harness is a _configurable
  value_ (e.g. `COLIBRI_AUTOSPAWN_BINARY=zot`), never baked into the name and
  always operator-overridable.
- **Harness-specific thing** (one harness's actual wire format) → the harness
  name belongs in it, and the parallels stay symmetric (`zot_event_type` ↔
  `pi_event_type`, `AgentRuntime::{Zot, Pi}`) so neither is privileged.

The `pi_*` rows in [Shipped](#shipped) are the cautionary tale: neutral concepts
wrongly named after a harness. Same applies to docs — a per-harness reference is
neutral (`AGENT-EVENTS-REFERENCE`), not `ZOT-…`, unless it is truly about one
harness only.
